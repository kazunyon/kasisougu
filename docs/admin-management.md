# 管理者支援ツールを使う

管理者支援ツールは、招待制登録の準備と日々の管理を支援します。試作画面の A01〜A04 に対応する管理画面は `admin.html`、L01 に対応する初回設定はローカルの対話型ツールです。管理画面は GitHub Pages へ公開し、管理操作は Supabase Edge Function が受け付けます。

## 使い始める前に

- Supabase Dashboard へ入れる担当者、Node.js/npm、Python 3.12 を用意します。事前にターミナルで `npx supabase login` を実行してください。
- 既存の招待運用から移行する場合は、`supabase/.invitation-secrets.env` を安全な保管先から元に戻します。登録キーの照合用秘密値を変更すると、以前のキーは利用できなくなります。
- 管理者として使うアカウントは、事前に招待を受け、メール確認とパスワード設定を済ませてください。まだ誰も登録されていない場合は、初回の1人を Supabase Dashboard の Authentication → Users から招待します。管理画面で登録キーを発行できるのは、この初回管理者の登録後です。
- Dashboard の Authentication で通常の新規登録を停止し、招待メールの送信元・SMTP と Redirect URL を設定します。これらは CLI だけでは完了しません。

## 初回設定（L01）

リポジトリのルートで、初回設定画面を開きます。

```powershell
python tools/admin_setup_gui.py
```

画面を使わずに進める場合や、Supabase CLI が接続時にパスワード入力を求める場合は、対話型コマンドを利用できます。

```powershell
python tools/setup_admin_management.py --project-ref YOUR_PROJECT_REF
```

別のURLで検証する場合は、画面の「アプリのオリジン」と「招待メールの戻り先」を変更します。コマンドでは `--app-origin https://example.jp` と `--redirect-url https://example.jp/kasisougu/invitation.html` を指定します。画面では接続先を確認し、未適用 migration の一覧を見てから「設定を反映」を押します。コマンドでは project-ref を再入力し、一覧を見て「反映」と入力します。**一覧には管理機能以外の変更も含まれることがあります。** 内容を確認して進めてください。

プロジェクトごとの秘密値ファイルは `supabase/.admin-secrets-<project-ref>.env` です。Git の対象外ですが、別の安全な保管先にも保存してください。既存の秘密値ファイルがある場合、ツールは登録キーと申込回数制限の秘密値を引き継ぎます。再実行時は同じファイルを使います。画面の「1. 接続先と変更内容を確認」で一覧を見てから、「2. 設定を反映」を押します。

GitHub Pages へ管理画面が公開された後、`https://kazunyon.github.io/kasisougu/admin.html` を開き、確認済みのアカウントでログインします。初回だけ、設定ツールが最後に表示した確認コードを入力して、管理責任者を登録します。この操作は、管理責任者がまだ1人もいない場合に限り成功します。

## 管理画面でできること

| 画面 | 管理責任者 | 招待担当 | 履歴閲覧担当 |
| --- | --- | --- | --- |
| 登録キーの状態を確認 | ○ | ○ | — |
| 新しい登録キーを発行・停止 | ○ | — | — |
| 利用者一覧、招待メール送信 | ○ | ○ | — |
| 利用停止・再開、担当者権限の付与・解除 | ○ | — | — |
| 操作履歴を見る | ○ | — | ○ |

新しい登録キーは、発行した直後の画面にだけ表示されます。画面を閉じた後で確認することはできません。発行時に渡す相手のメモを入力し、必要な相手にキーを安全な方法で伝えてください。管理画面では有効なキーの発行先メモと期限を確認できます。新しいキーを発行しても以前のキーは有効期限まで使えます。登録受付を止めると、すべてのキーが無効になります。

利用者一覧は50件ずつ表示します。検索欄は現在のページ内だけを絞り込みます。招待中の利用者には「招待を再送」を使えます。Supabase Auth が再送を拒否した場合は受信状況を確認してください。登録済みの方にはパスワード再設定を案内します。

利用停止は Supabase Auth の ban を使用します。新しいログインや更新を止めますが、発行済みアクセストークンを即座に失効させる仕組みではありません。停止操作の直後に既存セッションからの全データアクセスが止まる保証はないため、その要件が必要なら別途 RLS の停止判定を追加してください。

管理画面はログイン情報をブラウザーの保存領域に記録しません。ページを離れるとログアウトします。管理画面のURLを知っているだけでは管理操作はできず、各操作でEdge Functionが本人と権限を確認します。

## ログインできないとき

管理者ログインには、装具びよりで招待登録を済ませたアカウントのメールアドレスとパスワードを使います。初回の管理責任者は、先に通常の利用者としてログインできる状態にしてから、ログイン後に初回設定ツールの確認コードを入力します。

ログイン直後に「管理機能に接続できません」と表示される場合は、Supabase に `admin-management` Edge Function が配置され、`ADMIN_BOOTSTRAP_TOKEN` などの秘密値と管理用 migration が反映されているか確認してください。パスワード認証の前に「認証サーバーに接続できません」と表示される場合は、通信環境を確認してください。パスワードをこの手順書や問い合わせ文へ書かないでください。

## 運用上の注意

- 秘密値ファイル、初回確認コード、6桁の登録キーを Git、Issue、チャットの公開範囲へ載せないでください。
- 管理責任者自身や別の管理責任者は、管理画面から利用停止できません。管理責任者権限の付与・解除は、この画面では扱いません。
- 操作履歴は自動削除しません。保存期間を決め、必要になった時点で別途保守手順を用意してください。
- データベース・関数・管理画面を本番へ反映する前に、検証用プロジェクトで招待、停止・再開、権限と履歴を確認してください。
