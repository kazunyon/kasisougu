# 招待制の新規利用登録を設定する

このページは、運営担当者が「装具びより」の招待制登録を準備するための手順です。Supabaseの操作に慣れていない方も、上から順番に進めてください。利用者向けの登録案内ではありません。

**管理者支援ツールを使う場合：** 登録キー、秘密値、Edge Functionを個別に手で設定する代わりに、[管理者支援ツールの手順](admin-management.md)を参照してください。以下は手動で設定するときの手順として残しています。

## 最初に、登録の流れを確認します

1. 運営担当者が、利用者へ半角数字6桁の登録キーを伝えます。
2. 利用者がアプリでメールアドレスと登録キーを入力し、招待を申し込みます。
3. 登録キーが正しければ、Supabaseからそのメールアドレスへ招待メールが送られます。
4. 利用者がメール内のリンクを開き、パスワードを設定すると、アプリにログインできます。

登録キーを知っていることだけでは、本人確認はできません。メールを受け取れることを確認するため、利用者には必ず招待メールのリンクから登録を進めてもらいます。

## 作業前に用意するもの

- **検証用と本番用のSupabaseプロジェクト**：まず検証用で試し、問題がなければ本番用に同じ設定をします。
- **Supabase Dashboardに入れる管理者アカウント**：画面上の認証設定やメール設定に使用します。
- **このリポジトリのファイル一式**：コマンドは、`supabase`フォルダーがある場所（リポジトリのルートフォルダー）で実行します。
- **Node.jsとnpm、Python 3**：Supabase CLIは`npx supabase`で、登録キーの準備ツールは`python`で実行します。
- **検証用のメールアドレス**：招待メールを受け取り、最後まで登録できるか確認します。

**検証用のアプリ画面について：** 現在のGitHub Pagesは、`.github/workflows/pages.yml`で指定したSupabaseプロジェクトにつながります。別の検証用プロジェクトをアプリ画面から試すには、検証用プロジェクトにつながる画面と、その画面のURLに合わせた設定が必要です。検証用の画面がない場合は、画面からの一連の動作確認を完了できません。

以下では、ブラウザで操作する画面を「Dashboard」、コマンドを入力する画面を「ターミナル」と呼びます。Supabase CLIは、ターミナルからSupabaseを操作するためのツールです。初めて`npx supabase`を実行するときは、CLIの取得を求められる場合があります。

## 1. 検証用プロジェクトに設定する

### 1-1. 通常のメール登録を止める

Dashboardで**検証用プロジェクト**を開き、`Authentication`の設定から「Allow new users to sign up（新しい利用者の登録を許可する）」を無効にします。画面の配置が異なる場合は、`Sign In / Providers` → `Email`や認証の一般設定を確認してください。既存利用者のログインに使うメール認証は無効にしません。

この設定は、登録キーを使わずに通常の新規登録をする経路を止めるためのものです。設定後も、管理用の招待メールを送れるかどうかは、最後の動作確認で確かめます。

### 1-2. ターミナルを検証用プロジェクトへ接続する

リポジトリのルートフォルダーでターミナルを開きます。Supabase CLIにログインしていない場合は、先に次を実行してください。

```bash
npx supabase login
```

次に、Dashboardに表示される検証用プロジェクトのID（project-ref）を確認します。下の`YOUR_TEST_PROJECT_REF`を実際のIDに置き換えて実行してください。

```bash
npx supabase link --project-ref YOUR_TEST_PROJECT_REF
```

以降のCLIコマンドは、接続したプロジェクトに作用します。指定したIDが**検証用**のものであることを、次の操作に進む前に確認してください。

### 1-3. データベースの変更を反映する

まず、まだ反映されていない変更の一覧だけを表示します。`--dry-run`を付けたコマンドは、データベースを変更しません。

```bash
npx supabase db push --dry-run
```

一覧に`20260923130000_invitation_registration.sql`が含まれることを確認します。すでに反映済みなら一覧には表示されません。ほかの未適用ファイルも表示された場合は、それらも反映対象です。内容を確認してから次へ進んでください。

```bash
npx supabase db push
```

この変更で、登録キーの照合に使う記録場所と、招待申込の回数を制限する仕組みが作られます。登録キーやメールアドレス、IPアドレスをそのまま記録する仕組みではありません。

### 1-4. 6桁の登録キーを準備する

ターミナルで次を実行します。

```bash
python tools/prepare_invitation_key.py
```

画面の案内に従い、利用者へ伝える半角数字6桁の登録キーを2回入力してください。入力した数字は画面に表示されません。登録キーは設定と動作確認が終わってから、対象の利用者にだけ安全な方法で伝えます。

初回実行時には、照合用の秘密値を含む`supabase/.invitation-secrets.env`が作られます。ツールは登録キーそのものではなく、データベースへ登録するための計算結果（HMAC）とSQL文を表示します。SQL文は次の手順で使います。

**大切なこと：** `supabase/.invitation-secrets.env`はGit管理の対象外ですが、削除せず、信頼できる秘密情報の保管場所にも保存してください。登録キーを後で変更するときにも、このファイルの値を使います。ファイルの内容を利用者へ送ったり、公開したりしないでください。

検証用アプリを公開サイトとは別のURLに置く場合は、このファイル内の`APP_ORIGIN`を検証用サイトのオリジンに、`INVITATION_REDIRECT_URL`を検証用のパスワード設定画面のURLに変更してください。この変更は「1-6」の秘密値登録より前に行います。検証用アプリのビルド時にも、`SUPABASE_URL`と`SUPABASE_PUBLISHABLE_KEY`に検証用プロジェクトの値を指定します。

### 1-5. 登録キーの計算結果をデータベースへ登録する

検証用プロジェクトのDashboardで`SQL Editor`を開き、前の手順でツールが表示した**2行のSQL文**を貼り付けて実行します。1行目は現在有効なキーを停止し、2行目は新しいキーの計算結果を登録します。初回でも、表示された2行をそのまま実行してください。

登録キーには、SQL文に表示される有効期限があります。現在のツールでは、登録時点から90日後まで有効です。期限が切れる前に、運営担当者が新しいキーを用意してください。

### 1-6. Edge Functionに必要な秘密値を登録する

ターミナルの接続先が**検証用プロジェクト**であることを確認し、次を実行します。

```bash
npx supabase secrets set --env-file supabase/.invitation-secrets.env
```

このファイルには、キーの照合や申込回数の判定に使う秘密値と、アプリのURL設定が入っています。Supabaseが関数へ提供する`SUPABASE_URL`やAuth管理用キーを、自分でこのファイルに追加する必要はありません。秘密値をHTML、JavaScript、GitHub Pagesにも置かないでください。

### 1-7. 招待を受け付ける処理を配置する

ターミナルで次を実行します。

```bash
npx supabase functions deploy request-invitation
```

これで、利用者からの申込を受け付けるEdge Function（Supabase上で動く処理）が配置されます。申込者はまだログインしていないため、この処理はログイン前でも呼び出せる設定です。代わりに、処理の中で登録キーと申込回数を確認します。

### 1-8. 招待メールから戻る先を設定する

検証用プロジェクトのDashboardで`Authentication` → `URL Configuration`を開き、次を設定します。下の値は公開サイトのURLを使う場合の例です。検証用アプリを別のURLに置く場合は、そのURLに置き換えてください。

| 設定項目 | 入力する値 |
| --- | --- |
| Site URL | `https://kazunyon.github.io/kasisougu/` |
| 許可するRedirect URL | `https://kazunyon.github.io/kasisougu/invitation.html` |

招待メールのリンクを開いた利用者が、アプリのパスワード設定画面へ戻るために必要な設定です。

### 1-9. 招待メールの送信設定を確認する

Dashboardの`Authentication` → `Email Templates`で、`Invite User`（招待メール）の内容を確認します。メールの送信元とSMTP（メール送信サーバー）も設定し、検証用メールアドレスで受信できるか確かめてください。メールが届かない場合に誰が確認するか、リンクが期限切れになった場合にどう再招待するかも決めておきます。

## 2. 検証用プロジェクトで動作を確認する

本番の設定へ進む前に、次を順番に確認してください。

1. 間違った登録キーでは招待メールが送られず、利用者アカウントも作られない。
2. 正しい登録キーでは、入力したメールアドレスに招待メールが届く。迷惑メールフォルダーも確認する。
3. メール内のリンクからパスワードを設定でき、その後アプリへログインできる。
4. 通常の新規登録からはアカウントを作成できず、招待による登録はできる。
5. 繰り返し申込んだ場合に、設定した回数制限が働く。

申込画面は、登録キーが正しい場合も間違っている場合も、同じ受付メッセージを表示します。画面の表示だけで成功と判断せず、メールの受信とアカウントの状態まで確認してください。

申込回数の初期設定は、キーの誤入力が同じIPアドレスから15分間で5回まで、招待申込が同じメールアドレスから1時間に3回まで、同じIPアドレスから1時間に10回までです。これらの目安で動作を確認してください。

## 3. 本番プロジェクトに設定する

検証用プロジェクトで上記の確認が終わったら、本番用プロジェクトでも「1-1」から「1-9」を順番に実施します。`1-2`では、**本番用**のproject-refを指定して接続し直してください。`1-4`では本番で利用者へ伝えるキーを入力します。検証用に`supabase/.invitation-secrets.env`のURLを変更した場合は、本番用のURLに戻してから「1-6」を実行します。コマンドやSQLを実行する前に、DashboardとCLIの接続先がどちらも本番用プロジェクトであることを確認します。

登録キーのSQL、秘密値、Edge Functionは、本番用プロジェクトにも登録・配置する必要があります。Supabase側の設定が済んだら、アプリの変更もGitHub Pagesへ公開してください。両方が完了すると、利用者が招待制登録を使えるようになります。

## 運用を始める前の確認表

- [ ] 正しいキーだけで招待メールが届く。期限切れ・停止したキーでは届かない。
- [ ] 申込回数の制限が働く。同時に多数の申込があっても制限を超えない。
- [ ] 招待リンクからパスワード設定画面へ戻り、設定後にログインできる。
- [ ] 招待を承諾する前には本人データを読めず、設定後に`kasi_profiles`が作成される。
- [ ] 登録キーと秘密値が、公開ファイル、URL、エラー表示、ログ、`auth.users.user_metadata`に残らない。
- [ ] 非公開テーブルと管理用処理を一般利用者が直接利用できず、Dashboardの管理権限も運営担当者だけに与えている。
- [ ] 共有回線を使う利用者が、IPアドレス単位の制限で誤って利用できなくならないか確認した。

Supabase Dashboardから管理者が手動で利用者を追加する操作は、登録キーの確認を通りません。この操作ができる担当者を限定し、実施した理由と日時を記録してください。
